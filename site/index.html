    Run it yourself

    Install & launch in four commands

    # extras: [serve] web UI · [tui] terminal app · [openai] Stage 3
pip install "craft-tabqa[serve,tui]"

# build the index + row embeddings for your corpus (once)
craft preprocess --config configs/my_dataset.yaml

# retrieve the most relevant tables for each query
craft retrieve   --config configs/my_dataset.yaml

# explore interactively
craft serve      --config configs/my_dataset.yaml   # web UI at http://localhost:8000
craft tui                                            # menu-driven terminal app

    Custom-dataset format and full docs are in the GitHub repository.

    Overview

    What CRAFT is

    CRAFT finds the tables that answer a question. Given a large collection of tables and a natural-language question, it returns a short, ranked list of the most relevant tables — which you can then read, or hand to a language model to produce an answer. It is training-free: it composes off-the-shelf models into a pipeline, so there is no fine-tuning to run and nothing dataset-specific to label. That makes it straightforward to point at a new table collection of your own.

    The pipeline

    Three progressively precise stages

    Stage 1 · Sparse

    SPLADE

    Lexical retrieval over enriched table text narrows the full corpus to the top 5,000 candidates.

    Stage 2 · Dense

    Sentence Transformer

    Row-level dense reranking scores candidates against the query, keeping the top 100.

    Stage 3 · Rerank

    Final reranking

    A reranker or embedding model — open-source or API — orders the shortlist into the final top-k. This stage is swappable, so you can pick the model that fits your setup.

    🔍

    Query expansion

    An LLM generates sub-questions that broaden lexical coverage of each query.

    📋

    Table enrichment

    Each table gets an LLM title + summary, bridging the lexical gap with natural-language queries.

    ✂️

    Mini-tables

    Top query-relevant rows form a compact mini-table, cutting context up to 5×.

    Benchmarks

    Datasets it comes configured for

    CRAFT ships with configs for two open-domain table-QA benchmarks. You can also point it at your own table collection.

    Single-hop

    NQ-Tables

    Wikipedia tables where each question is answered by a single table.

    Multi-hop

    OTT-QA

    Questions that reason across tables and passages.

    Answering the question

    Compact tables, smaller context

    Once the top tables are retrieved, CRAFT can pass them to a language model to produce an answer. It sends mini-tables — each table's most relevant rows and its headers — rather than whole tables, so the context stays small enough for lightweight models to read.
